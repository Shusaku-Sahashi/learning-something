# 🔍 第2章 プロパティの見つけ方（Example 11–22）

## この章のゴール

「何を書けばいいか分からない」を解決します。
プロパティは**型ではなくパターンで覚える**のがコツです。

## 9つのパターン

| # | パターン | 形 | Example |
|---|---|---|---|
| 1 | 往復 (round-trip) | `decode (encode x) == x` | 11, 12 |
| 2 | 不変条件 (invariant) | `always (p (f x))` | 13 |
| 3 | 冪等性 (idempotence) | `f (f x) == f x` | 14 |
| 4 | 代数法則 | 結合律・交換律・単位元 | 15 |
| 5 | テストオラクル | `f x == slowButObviouslyCorrect x` | 16 |
| 6 | メタモルフィック関係 | 「入力をこう変えたら出力はこう変わる」 | 17 |
| 7 | 構造に沿った性質 | `f (xs ++ ys) == f xs <> f ys` | 18 |
| 8 | 全域性 | `total (f x)`（落ちない） | 19 |
| 9 | 同じ計算の2つの書き方 | `newImpl x == oldImpl x` | 20 |

## それぞれの使いどころ

### 1. 往復

encode/decode、シリアライズ、パーサと pretty printer、URL エンコード、圧縮。
**実務で一番よくバグが見つかります。**

注意：往復が成り立つのは `encode` が単射のときだけです。
情報が落ちる変換（pretty printer の空白など）では、逆向きは成り立ちません。

### 2. 不変条件

**1つでは足りません。** Example 13 では、`sort` の代わりに「常に `[]` を返す」実装が
「結果は昇順である」を満たしてしまいます。

> 目安：**この性質を全部満たす、間違った実装を書けるか？**
> 書けるなら、プロパティが足りていません。

### 3. 冪等性

正規化、整形、重複除去、ソート。「もう一度やっても何も起きないはず」の関数。

破れる典型：
- 「あれば足さない」はずが常に足している（`ensureTrailingNewline`）
- エスケープ処理を二重にかけてしまう

### 4. 代数法則

自作の型クラスインスタンスを書いたら**必ず**確認してください（第4章 Example 43 で詳しく）。

### 5. テストオラクル

一番手軽で一番強力。性質を考えなくて済みます。

- 自作の速い実装 vs 標準ライブラリの素朴な実装
- 最適化後 vs 最適化前（リファクタの安全網）
- 並行版 vs 逐次版
- 移植先 vs 移植元

コツ：**「明らかに正しいが遅い」実装をオラクルに選ぶ。**

### 6. メタモルフィック関係

「正解が計算できない関数」にも書けます。検索ランキングや機械学習モデルのテストで使われます。

テンプレート：
- 入力を並べ替えたら？ → 結果は同じ／同じように並べ替わる
- 入力を1つ足したら？ → 結果は単調に増える
- 入力を2つに分けたら？ → 結果は合成できる
- 入力を空にしたら？ → 単位元が返る

### 8. 全域性

性質を1つも思いつかなくても、これだけは書けます。

```haskell
prop_neverCrashes :: Input -> Property
prop_neverCrashes x = total (myFunction x)
```

`head` / `fromJust` / `!!` / `div` の踏み抜きを検出できます。

## 最重要：プロパティ自身をテストする

Example 22 の STEP 4 が、この章で一番大事な部分です。

**わざと壊した実装を入れて、テストが落ちることを確認してください。**
落ちないなら、そのプロパティは何も守っていません。

これは変異テスト (mutation testing) の手動版です。
第9章 Example 99 で本格的に扱います。

## チェックリスト

プロパティを探すときに、順に自問してください。

1. 往復するものはないか（encode/decode, insert/lookup）
2. 変わらないものは何か（長さ、要素の集合、順序）
3. 2回やったら同じか（正規化、ソート、削除）
4. 代数法則を満たすか（結合律、交換律、単位元）
5. 比べられる別実装はないか（標準ライブラリ、素朴な実装、旧版）
6. 入力を変えたら出力はどう変わるか（単調性、分配則）
7. 構造に沿った性質はあるか（`++` や `:` に対する振る舞い）
8. とにかく落ちないか（`total`）
