# 01. JSON の文法とパースの基礎

実装に入る前に、JSON の文法とパースという作業そのものについて最低限のことを
押さえておきます。ここはコードを書かない回です。

## JSON のデータ型

JSON には4つのスカラー型と2つの複合型しかありません。

- スカラー型
  - `null`
  - 真偽値: `true` / `false`
  - 文字列: `"..."` で囲まれた Unicode 文字の並び
  - 数値: 整数部・小数部・指数部からなる数値(整数部は必須、小数部と指数部は省略可)
- 複合型
  - 配列: `[` `]` で囲まれた値のカンマ区切りリスト
  - オブジェクト: `{` `}` で囲まれた `"キー": 値` のカンマ区切りリスト

配列とオブジェクトは「値」を要素として持ち、値は「配列やオブジェクトでもよい」ので、
JSON の文法は**再帰的**です。これが後々 `jValue` パーサが `jArray`/`jObject` を、
`jArray`/`jObject` が `jValue` を呼び合う(相互再帰)理由になります。

[JSON Value の構造(図解)](https://claude.ai/code/artifact/f1587504-acff-4abd-9aa9-2102cef874a8#json-value)
も参照してください。

数値の細かい注意点だけ先に触れておきます。

- 整数部の先頭に `0` が続くのは NG (`012` は無効。`0` 単体は OK)
- 小数点の後は必ず1桁以上の数字が必要 (`1.` は無効)
- 指数部 (`e`/`E`) の後は必ず1桁以上の数字が必要 (`1.23e` は無効)
- 正の符号 `+` は整数部には付けられない (指数部にはつけてもよい)

有効な例: `0`, `1234`, `1.23`, `0.222`, `1e5`, `5E-45`, `1.23e9`
無効な例: `012`, `1.`, `.123`, `1.23e`

正確な文法は [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259) が原典です。

## パースとは何か

パース(構文解析)とは、テキストを読んでその構造をチェックしながら、
何らかのデータ構造(多くの場合、木構造)に変換する作業です。今回のゴールは、
JSON テキスト(`String`)を Haskell の `JValue` という代数的データ型に変換する
関数を書くことです。

```
"{\"a\": 1, \"b\": [false, null]}"
   ↓ パース
JObject [("a", JNumber 1 [] 0), ("b", JArray [JBool False, JNull])]
```

パーサの実装方式にはいくつか流儀がありますが、今回採用するのは**パーサコンビネータ**
という方式です。考え方はシンプルで:

1. 「1文字だけパースする」のような、ごく小さいパーサをいくつか用意する
2. それらを**組み合わせる**ための道具(高階関数)を用意する
3. 小さいパーサを道具で組み合わせて、少しずつ大きいパーサを作っていく

例えば「1桁の数字をパースする」パーサを組み合わせれば「整数をパースする」パーサが
作れますし、それをさらに組み合わせれば「JSON の数値をパースする」パーサが作れます。
JSON の文法をそのまま Haskell のコードに翻訳していくような感覚に近く、
今回のシリーズを最後まで終えると「文法の定義とコードがほぼ1対1に対応している」ことに
気づくはずです。

そしてこの「組み合わせるための道具」の正体こそが、これから学ぶ
`Functor` / `Applicative` / `Monad` / `Alternative` です。抽象的な概念を先に暗記する
のではなく、「この組み合わせ方が欲しい」という具体的な必要性が先にあって、
それにちょうど当てはまる型クラスが後から出てくる、という順番で進めます。
